# MicroFlow 外部功能接入规范

版本：v1.0
日期：2026-10-24
状态：设计基线。本规范是《前端框架完整设计方案 v1.12》（下称"基线设计"）接入面的操作化收敛：只汇总、排序与补充验收清单，不引入新语义。与基线设计冲突时，以基线设计为准；需要新语义时，先修订基线设计并同步 §44.4 示例与一致性基线，再修订本规范。

## 1. 定位与范围

MicroFlow 框架只提供有限的基础能力（算子开发、编排、版本管理、数据统计的底层协议）；具体算子、编排配置写入、配置版本选择、AB 实验、运营数据采集与 bug 数据分析均由上层实现。本规范回答一个问题：**外部功能经由哪些已声明通道进入框架，交付什么，如何判定接入合格。**

"外部功能"按承载物归属三类接入方，对应基线设计的三个平面（§2.9）：

| 接入方 | 承载内容 | 进入通道 | 权威章节 |
|---|---|---|---|
| 宿主实现（代码平面） | 元组件、组件、Local Function、数据适配器、宿主能力、布局能力、样式资产、Renderer | 统一资源注册协议（构建期注册 / 运行期注入） | §5、§7、§10.1、§12.1、§17、§23、§36、§40 |
| 上层工具（配置平面） | 编辑器、CLI、AI Agent；编排配置创作、命令执行、findings 回流 | 结构化命令面与项目模型读写协议 | §2.7、§14、§15、§18.3、§43.3 |
| 平台服务（数据平面） | 遥测接收、查询导出、订阅、实验/运营变体分流、Debug 远程诊断、身份服务 | 各 Provider / Ingest / Query 契约 | §24、§29、§30、§31、§32、§43 |

规则：

- 框架不内置任何具体平台、编辑器或业务组件（§27）；任何接入方不得要求框架新增对其私有的通道；
- 实现语言无关：核心协议不解释实现语言，兼容判断只依赖契约（§23.2）；
- 本规范的每一条规则都标注基线设计章节出处，供接入方回溯权威定义。

## 2. 通用接入纪律

以下八条对所有接入方生效，违反任意一条即接入不合格：

1. **契约先行**：每项接入交付物必须有版本、Schema、稳定错误码、兼容范围、能力声明、降级策略和契约测试；只有文字纪律而无最小 Schema 的契约视为未定义，不得进入发布清单（§18.4、§27）。
2. **归属唯一**：每个资源与值恰好归属一个平面；平面间交互只走已声明通道（§2.9）。
3. **显式注册**：未注册引用是静态错误；不存在隐式发现或隐式代码执行通道（§2.7、§23.11）。
4. **版本与兼容**：接入资源按 `id + version + compatibility` 管理；多版本并存时解析必须确定且跨实现一致，解析结果随引用进入发布快照（§23.4、§4.2）。
5. **信任边界**：核心框架不动态执行任意项目目录中的代码；运行期注入必须经 platform profile 声明的入口（入口允许清单或实现签名），注入主体、目标和结果进入审计（§23.3、§32）。
6. **可判定降级**：能力不足、权限拒绝、暂不可用和结果未知必须是可判定状态，并按声明降级或进入错误边界；禁止静默降级（§22.1、§12.1、§17.1）。
7. **诊断码登记**：全部静态错误、运行诊断和契约诊断使用 `mf.<area>.<name>` 命名空间，且必须在统一注册表登记；发射未登记诊断码视为实现缺陷（§41）。
8. **审计与最小化**：注册清单变更、发布、回滚、配置下发、注入、Debug、查询、导出和实验配置的操作主体、角色、作用域与授权依据进入审计；凭据不得写入模型、契约、日志、快照或事件（§32）。

## 3. 代码平面接入：宿主实现资源

### 3.1 可接入类别与差异面

统一资源注册协议对全部类别执行同一公共纪律，各类别只声明差异面（§23.11、§23.12）：

| kind | 差异面契约 | 关键交付要求 |
|---|---|---|
| component | §23.2：props / slots / events / states / layout / exposed_styles / platform_variants / accessibility | 结构传递与宿主生命周期契约（§23.9、§23.10） |
| primitive | §5 全量契约 + 样式面（§36.5）+ 布局能力（§7）+ 可访问性 | 须同时提供预览实现与运行实现（§17） |
| function | §10.1 Action Contract：input / output / errors / timeout_ms / idempotency / cancellation / unknown_result | 只能由 Local Function 代码实现 |
| adapter | §40.2 Data Contract：input / output / errors / idempotency / cache / staleness / permissions / privacy_class / trace | 不得携带 UI 类字段；契约未登记不得注册 |
| capability | §17.1 Capability Contract：states / permissions / availability / degradation | 五个可判定状态缺一不可；缺失降级声明不得注册 |
| layout | 与 §7.3 同构的形式化求解规则 + 编译器检查规则 + 各目标 Renderer 映射 + 降级策略 | 缺检查规则的布局能力不得注册、不参与约束求解 |
| style-asset | §36 Schema（token-set / theme / style） | 声明式资源，不携带实现、不适用注入通道 |
| renderer | §12.1 Renderer Contract + platform profile + 能力矩阵 | 通过 §44.3 基线后方可声明分级（§38.2） |

差异面字段不属于可选声明：注册清单包含差异面之外未登记的 kind 专属字段时产生 `mf.reg.unknown-field` 诊断（§23.12、§41）。

### 3.2 注册清单公共字段

全部 kind 的注册清单统一携带（§23.11；字段纪律同 §4.2、§23.2）：

```text
id、kind、revision、description、dependencies、capabilities、
tests、version、compatibility、deprecation
```

`dependencies` 声明运行期依赖的其他注册资源；未声明的依赖在解析失败时按 §23.5 处理，禁止隐式发现。`tests` 指向契约一致性测试（§33 测试层）。

### 3.3 双注册通道

注册分两个通道，两者执行同一 Schema 校验与兼容检查（§23.3）：

1. **构建期注册**：注册清单作为模型资源进入项目模型，编译器校验契约、引用与兼容范围，并为每个目标 Renderer 生成绑定产物；
2. **运行期宿主注入**：解释模式或宿主平台启动时经实现装载器注入实现；注入的契约摘要必须与注册清单一致，实现与声明不符是运行错误并进入错误边界，禁止静默降级。

未通过声明入口到达的实现按未注册处理，产生 `mf.reg` 诊断并进入错误边界。

### 3.4 结构传递与生命周期

- 宿主实现组件的插槽接收规范化节点描述，不是可变对象图；宿主实现不得读取插槽子树内部状态、不得反向修改子树或项目模型（§23.9）；
- 生命周期钩子按契约声明：未声明的钩子运行时不调用；钩子属于 §24.7 拦截边界，宿主实现不得在钩子内直接调用采集（§23.10）。

### 3.5 版本并存、废弃、注销与发现

- 同一 id 多版本并存，解析规则见 §23.4；歧义未消歧是静态错误；
- 废弃是显式声明（废弃版本、替代资源、移除版本），废弃资源继续通过校验但产生警告；
- 注销前必须通过引用检查（§4.3），保留墓碑记录，历史发布快照不受影响（§23.6）；
- 注册表提供发现查询（已注册资源、契约摘要、可用版本、影响范围），供工具、AI 与编译器使用（§14 `register_resource`、`inspect_impact`）。

### 3.6 接入流程

```text
1. 声明差异面契约（按 §3.1 表交付对应 Schema）
2. 交付注册清单（§3.2 公共字段 + 差异面字段）
3. 交付契约一致性测试（§33）与降级策略
4. 注册：构建期进入注册清单，或经声明入口运行期注入（§3.3）
5. 静态检查：未注册引用、契约缺失、类型不匹配、兼容范围、越界字段（§23.7）
6. 引用与编排：纯配置引用已注册资源（§2.7）
7. 进入发布快照：解析结果、契约摘要与依赖随快照冻结（§16、§23.4）
8. 兼容跟踪：破坏性变更提供迁移器与诊断码；废弃→注销走墓碑（§23.4、§23.6）
```

## 4. 配置平面接入：上层工具

### 4.1 工具接入面

框架不提供可视化编辑器。编辑器、CLI 与 AI Agent 作为上层客户端接入以下协议面（§14、§19 阶段六）：

- 项目模型读写（版本化修订，非原地改写）；
- 结构化命令（§4.2）；
- 局部上下文查询（按任务裁剪：当前页面 → 图层 → 组件 → 状态 → 交互 → 受影响资源）；
- 影响分析（`inspect_impact`，基于 §4.3 反向索引）；
- 差异预览、修改审计与可回滚修订。

### 4.2 结构化命令面

AI 与工具操作必须使用结构化命令，不得以自由文本绕过 Schema、权限和编译检查（§14）：

```text
create_component    update_component    insert_layer
replace_page_variant    connect_navigation    add_interaction
create_page    create_page_from_template
register_component    register_resource    rename_resource
inspect_impact    validate_project
```

命令面覆盖全部注册资源类别：`register_component` 注册宿主实现组件，`register_resource` 按 kind 注册元组件、数据适配器、布局能力、样式资产、本地函数与宿主能力（§23.11）；`inspect_impact`、`validate_project` 对全部类别生效。

每次命令执行必须产生：修改目标、修改前后摘要、影响对象、验证结果、未解决问题和可回滚修订（§14）。

### 4.3 纯配置构造边界

配置构造是封闭集合：页面、图层、模型组合组件、导航边、绑定映射、i18n 文案、主题覆盖与样式片引用仅凭配置可建；元组件实现、宿主组件、Local Function、外部适配器、宿主能力与 Renderer 扩展必须代码修订并显式注册，配置侧不存在绕行通道（§2.7）。纯配置创建不降低任何门禁：新页面走同一校验，模型结构变化产生新发布快照。

### 4.4 配置创作与配置版本

- 配置平面创作形态位于项目目录 `config/`：默认配置、内容资产、运营变体与实验上下文；每份配置携带 `config_id`、`config_version`、`schema_version` 与内容摘要（§15、§4.5）；
- 默认配置随发布快照冻结；动态下发配置以 `config/` 版本为可追溯源头，创作、校验与下发不使用两套口径；
- 文案归属 i18n 还是内容资产按 §42.7 唯一判定规则执行，双声明是静态错误；
- 实验与运营变体允许配置改写的资源面必须逐条登记于受控交叉清单；未登记的改写在静态校验中拒绝（`mf.exp.variant-out-of-scope`）（§2.9、§24.4）。

### 4.5 合格客户端判定

工具接入是否合格，以其能否通过 §18.3 一致性回归为准：

- AI/工具修改后对象 ID 不丢失；
- 未修改页面不产生无关差异；
- 组件修改能正确报告影响页面；
- 解释模式与编译模式行为一致；
- 发布结果可重复生成；
- 删除资源不留下隐式引用。

不得自建平行事实来源：工具的所有读写必须经由项目模型与结构化命令，工具本地的缓存、草稿与索引只是派生数据（§14、§17.2）。

### 4.6 数据回流

运营结论、bug 聚类、实验结论以 findings 注记回流（§43.3）：

- findings 必须符合版本化 Schema，按 `finding_id` 引用登记，不得以自由文本替代；
- `regression-key` 类型必须绑定可执行的校验命令或用例引用；
- 回流是流程与来源标注，不自动修改模型：结论触发的修改仍走结构化命令、验证与审计。

## 5. 数据平面接入：平台服务

### 5.1 遥测接收、查询导出与订阅

- **接收端**（§30.1）：业务层按协议承载，必须实现批量、压缩、退避、取消、断网缓存、有界队列、`event_id` 去重、Schema/隐私校验、丢弃原因记录；普通事件丢失不阻断核心流程，Business Fact 走提交确认与未知结果查询；
- **查询与导出**（§30.2）：`query_events` / `get_event_schema` / `get_trace` / `export_events` / `get_data_quality`；过滤器必须有界，导出走游标增量并声明缺口区间，禁止静默改写已交付数据；
- **订阅**（§43.2，可选）：`subscribe(filter, cursor)`，过滤器与查询同构，at-least-once，消费方按 `event_id` 去重，背压通过游标回退实现；
- 事件信封与标准事件族字段口径按 §24.2 执行；标准族由运行时拦截边界零埋点产生（§24.7），业务代码手工上报标准族是静态错误。

### 5.2 实验与运营变体 Provider

外部实验平台/配置中心通过 Provider 接入，不直接修改运行时状态（§31）：

```text
resolve_assignment(experiment_id, subject_scope, release_context)
get_experiment_config(experiment_id, assignment_id)
record_exposure(exposure_event)
get_experiment_status(experiment_id)
```

规则：

- 框架只做校验（Schema、平台能力、发布版本、有效期、兼容范围）、冻结应用与上报；分流算法、样本选择、启停与结论由外部控制方完成（§24.4）；
- `assignment.variant` 必须命中 `variants`；停用只停止新曝光，不改写历史归属（§31、§24.5）；
- 非实验的运营变体配置（§31.1）复用同一 Schema 但不携带 `assignment_id`，不得伪装成实验分配进入实验数据面；
- Provider 不可用、配置过期或不兼容时使用发布快照默认变体并记录降级原因（§24.4）。

### 5.3 Debug 远程诊断

Debug 分本地、预览和生产受控三级，全部经权限、环境与数据分类检查（§29）：

- 会话携带 `principal`、`level`、`scope`、`grants`、`expires_at` 与 `audit_ref`；`grants` 逐项授权，未授予的操作拒绝并审计；
- 生产默认禁止任意暂停；快照限制大小、深度、保存时间，并按 `privacy_class` 屏蔽字段；
- 远程诊断服务由业务层承载，Renderer 落地会话与快照协议（§27 责任矩阵）。

### 5.4 身份与隐私

- 事件身份字段（`identity.user_ref` / `device_ref` / `exp_subject_ref`）全部为受控哈希或随机不透明标识，由身份服务颁发；任何事件不得携带原始凭据或直接标识（§24.2、§4.4）；
- 采集同意、字段屏蔽、保留与删除、跨租户隔离、第三方依赖签名与撤销按 §32 执行并进入发布门禁；
- 追踪身份是标识不是凭据：跨栈上下文不得携带令牌或可用于鉴权的内容（§24.8）。

### 5.5 跨栈追踪

声明了追踪传播（Data Contract `trace` 字段，§40.2）的适配器调用由运行时注入上下文（至少 `trace_id`、`release_id`、页面实例标识、`action_request_id`）；外部执行侧返回的运行引用按不透明标识进入诊断、事件与 Debug 快照（§24.8）。Business Fact 的确认必须关联外部运行引用；没有可关联引用的确认只能进入 `unknown`，不能当作成功。

## 6. 门禁与验收

### 6.1 静态与运行门禁

接入产物并入以下门禁，任一未通过不得进入发布清单（§18.1、§22.4、§23.7、§40.6、§24.6）：

- Schema、规范化、引用索引与资源注册契约一致性检查通过（全类别）；
- 三平面分离检查与受控交叉清单校验通过（§2.9）；
- Data Contract、Action Contract、Capability Contract、Recovery Contract、Renderer Contract、Performance Contract、Telemetry Contract、Experiment Contract 全部有 Schema、版本与诊断码（§18.4）；
- 外部能力不可用时按契约降级或失败，未知结果副作用不自动重试；
- 观测与实验门禁：事件 Schema/隐私/采样/保留通过检查，曝光只在真实曝光后产生，标准族零埋点口径校验通过。

### 6.2 接入方自查清单

| 接入方 | 必交交付物 | 判定依据 |
|---|---|---|
| 宿主实现 | 差异面契约 Schema、注册清单、契约一致性测试、降级策略、兼容范围 | §3.1–§3.6；§23.7；§44.3 相关基线 |
| 上层工具 | 命令面接入说明、修改审计与回滚证据、§18.3 回归结果 | §4.1–§4.6；§18.3 |
| 遥测接收/查询 | §30.1/§30.2 协议实现、数据质量指标、保留与删除策略 | §5.1；§24.6；§43.1 |
| 实验/变体 Provider | 四方法实现、校验与冻结证据、停用与默认变体降级证据 | §5.2；§24.6 |
| Debug 服务 | 会话授权/过期/撤销实现、快照屏蔽与预算证据 | §5.3；§29 |
| Renderer | §12.1 契约声明、§38.2 分级证据、§44.3 全量基线 | §3.1 renderer 行；§33 |

## 7. 与当前实现的映射

以 MicroFlow4Flutter 0.2.0 为参照（实现状态以子项目 README 与测试为准，本表随实现修订同步）：

| 协议面 | 当前状态 |
|---|---|
| 统一资源注册（§23，构建期通道） | 已实现注册/静态校验门禁；运行期注入通道未实现 |

## 8. 修订规则

- 本规范随基线设计一起版本化；基线设计发生影响接入面的修订时，本规范在同一修订周期内同步；
- 本规范只收敛与引用基线语义；需要新增接入通道、新增契约字段或新增诊断码时，先修订基线设计并同步 §44 示例与一致性基线，再修订本规范，避免两份权威版本漂移。
